# Serafin — agent guide

Serafin is a native SwiftUI client for Jellyfin on iPhone and iPad. It exists to be the prettiest, most Apple-native way to watch a Jellyfin library. Read this file in full before touching code. The phased work plan is in `docs/PLAN.md`; work through it in order, one task at a time.

## Mission, in priority order

1. **Pretty.** Artwork first. Liquid Glass used the way Apple uses it. Motion that feels physical. If a screen would not look right as an App Store screenshot, it is not done.
2. **Native.** Standard components and system behaviours over custom chrome. Tab bar, sheets, context menus, Now Playing, PiP, Dynamic Type and VoiceOver all come from the platform.
3. **Simple.** A short feature list, each item finished. Cut a feature before shipping it half-done.
4. **Secure.** Tokens in the Keychain, TLS by default, the app collects nothing about the user.

Out of scope until after 1.0. Do not build, scaffold, or stub these: downloads, Live TV, music, books, photos, tvOS, macOS app target, SharePlay, VLCKit, widgets, analytics of any kind.

## Naming and branding

- Product name: **Serafin**. Bundle display name `Serafin`. App Store listing name `Serafin for Jellyfin`.
- Bundle ID: `app.getserafin.serafin`. Website: `getserafin.app`.
- Never use "Jellyfin" as part of the product name. "for Jellyfin" in a subtitle or description is permitted by Jellyfin's branding policy; "Jellyfin Serafin" is not.

## Toolchain

- Xcode 26 or later. The owner builds with Xcode 27 and the iOS 27 simulator; CI builds with Xcode 26.6 and tests on an iOS 26.5 simulator, so the iOS 26 floor is checked on every PR. Code must compile on both. Swift 6 language mode, strict concurrency checking set to complete.
- Deployment target iOS 26.1 and iPadOS 26.1, the first release that can hide the tab bar's bottom accessory when nothing is playing (`tabViewBottomAccessory(isEnabled:)`). No `#available` branches for older OS versions; the floor is the floor.
- The Xcode project is generated by XcodeGen from `project.yml`. `brew install xcodegen`, then `xcodegen generate` after any change to `project.yml`. The `.xcodeproj` is gitignored; never hand-edit it.
- Formatting: the toolchain's `swift format`, configured by `.swift-format` at the repo root. Run it before every commit.
- Dependencies are Swift packages only. Allowed: `jellyfin-sdk-swift` (product `JellyfinAPI`) and `Nuke` (products `Nuke`, `NukeUI`). Anything else needs a one-paragraph justification in the PR and the owner's approval first.

### Commands

## Architecture

Four library targets in one local package, plus a thin app target. Dependencies point one way:

```
App → SerafinFeatures → SerafinDesign
                      → SerafinPlayback → SerafinCore
                      → SerafinCore
```

Rules, enforced by `Package.swift` target dependencies and by review:

- `SerafinDesign` depends on nothing in the project. It never imports `SerafinCore`, `JellyfinAPI`, or Nuke's networking. Every component renders from plain value types and `MockMedia` fixtures, so every preview works offline.
- `SerafinCore` has no UI. It owns `JellyfinClient` construction, auth, the server registry, the Keychain store, the device identity, the image URL builder and the shared `ImagePipeline` configuration.
- `SerafinPlayback` depends on `SerafinCore`, the SDK's models (`JellyfinAPI`) for the device profile and playback info, and AVFoundation only. UIKit use (PiP controller, player layer hosting) is wrapped in `#if canImport(UIKit)` so the package still builds for macOS, which keeps `swift test` runnable on the host and keeps the door open for a Mac app later.
- `SerafinFeatures` composes the other three into screens. It uses the SDK's generated models directly; add a mapping type only where a screen needs a shape the SDK does not provide.
- `App` contains only the `@main` entry, scene setup, deep-link routing and asset catalogs.

## Code conventions

- Screen state lives in `@Observable @MainActor final class <Screen>Model`. Views are structs; extract a subview once a body passes roughly 60 lines.
- `async`/`await` only. No Combine, no completion handlers, except where the SDK hands you a publisher and you bridge it with `.values`.
- Stores that hold shared mutable state (`ServerStore`, `SessionStore`, caches) are `actor`s.
- Errors: one `SerafinError` enum per layer boundary with a user-facing `LocalizedError` description mapped in Features. Never show a raw `URLError` or decoding error to the user.
- Logging: `os.Logger(subsystem: "app.getserafin.serafin", category: "<area>")`. Every URL, token, username, server name and item title is logged with `privacy: .private`. Release builds log at `.error` and above only. No `print`.
- No force unwraps, no `try!`, no `fatalError` outside of truly unreachable `switch` defaults.
- Strings: `String(localized:)` with English as the base language in `Localizable.xcstrings`. No hard-coded user-facing text in views.
- Accessibility: every card, button and control has an accessibility label; cards include title, year and progress ("Sintel, 2010, 40% watched").
- Images: `NukeUI.LazyImage` through the shared pipeline from `SerafinCore`. Always request a sized image URL (`maxWidth`) matching the view, never a full-resolution poster in a grid.
- Previews: every component in `SerafinDesign` has `#Preview` variants for light, dark and the largest accessibility text size, using `MockMedia` only.
- Tests: `swift-testing` (`import Testing`), not XCTest, for new tests.

## Design rules

Glass is the navigation and control layer floating over content. Content itself is never glass, and glass never sits on glass. Everything else follows from that.

- Artwork is the background. Full-bleed backdrops on detail screens, posters on home and library. Glass earns its look from what is behind it.
- Use the system `TabView`, toolbars, sheets, `searchable` and context menus. They are already glass and already correct. Do not rebuild them.
- Apply `.glassEffect()` only to custom floating controls: player controls, filter chips, the mini player, the play pill on a hero. Group neighbours in a `GlassEffectContainer` so they merge and morph together. Use `.interactive()` only on controls that can be tapped.
- One accent colour per screen, derived from the artwork's dominant colour and applied as a glass tint, never as a flat fill.
- Corner radii are continuous (`.rect(cornerRadius:style: .continuous)`), from a scale of 12, 16, 24.
- Motion: `.spring(.snappy)` by default; `.animation(nil)` on anything that scrolls. Honour Reduce Motion and Reduce Transparency; glass must fall back to a plain material.
- Haptics through `.sensoryFeedback`, on play, mark played, scrub detents and pull to refresh. Never on scroll.
- Dark and light appearance are both first-class; glass tints are tuned for each.

Platform APIs to reach for (verify the exact signature in the SDK headers from Xcode before use; do not invent modifiers):

- `.glassEffect(_:in:)`, `GlassEffectContainer`, `.glassEffectID(_:in:)` with `@Namespace`, `.buttonStyle(.glass)` and `.buttonStyle(.glassProminent)`.
- `Tab(role: .search)` for the search tab, `.tabBarMinimizeBehavior(.onScrollDown)`, `.tabViewBottomAccessory` for the mini player, `.tabViewStyle(.sidebarAdaptable)` for the iPad sidebar.
- `.navigationTransition(.zoom(sourceID:in:))` with `.matchedTransitionSource` for poster-to-detail.
- `.hoverEffect(.lift)` on cards for iPad pointer.

## Security requirements

These are requirements, not preferences. A PR that violates one is not mergeable.

| Risk | Requirement |
| --- | --- |
| Password theft | Passwords are never persisted anywhere. Quick Connect is the default sign-in. Password login sends credentials once over TLS and keeps only the returned access token. |
| Token theft from device | Tokens live in the Keychain with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, one item per server and user, excluded from iCloud Keychain and backups. No tokens in UserDefaults, SwiftData, files or logs. |
| Token leak in transit | HTTPS by default with App Transport Security on. Plain HTTP is allowed only for private addresses (10/8, 172.16/12, 192.168/16, `.local`, localhost, and Tailscale's 100.64/10, which only exists inside an encrypted tailnet) after an explicit, non-dismissable warning, and never for public hosts. The only ATS key permitted in Info.plist is `NSAllowsLocalNetworking`. |
| Self-signed certificates | No global ATS exception. The user is shown the SHA-256 fingerprint once and pins it; the `URLSessionDelegate` accepts only that public key for that host. Pins are stored in the Keychain. |
| Token in URLs | API calls carry the token in the `Authorization` header. Stream URLs must carry it as a query parameter because AVPlayer cannot add headers to HLS segment requests; that is acceptable only over TLS, or over plain HTTP to a private address the user has accepted (where the header already carries the token in the clear), and such URLs are never logged. Image requests use the header, not a query parameter. |
| Token leak in logs | OSLog with `.private` on every secret or identifying value. Never log a full request or response. |
| Stale sessions | Sign-out calls the server's logout endpoint and deletes the Keychain item. Each install registers a stable device ID (UUID generated once, stored in the Keychain) and client name `Serafin` with the app version, so users can see and revoke it in the Jellyfin dashboard. |
| Third-party exfiltration | No analytics, ad, or crash-reporting SDKs. Dependencies are pinned to exact versions in `Package.resolved` and reviewed for network calls. |
| Device shared or lost | Optional Face ID / Touch ID lock on launch via `LocalAuthentication` (Phase 2). Cached metadata and images use iOS data protection and can be cleared from Settings. |
| Malicious server | Every server response is untrusted input: bounded decoding, no HTML rendering of overviews or descriptions, image loading confined to the image pipeline, no `javascript:` or `file:` URLs ever opened. |

## Definition of done, every task

- `xcodegen generate` and the build succeed with zero warnings.
- `swift test` and `xcodebuild test` pass. New logic in Core or Playback has tests; new UI has previews.
- Previews for any touched component render in light, dark and the largest accessibility size without clipping.
- No new dependency, no new ATS key, no new entitlement, unless the task says so.
- Public API in the packages has a doc comment.
- Formatting applied.
- PR description includes a screenshot or screen recording for any UI change and lists which `docs/PLAN.md` task it completes.

## How to work

- One task from `docs/PLAN.md` at a time, in order. Before starting, write a five-line plan of the files you will touch. After finishing, run the definition of done.
- Branch per task: `feat/<phase>.<task>-<slug>` (for example `feat/1.3-quick-connect`). Conventional commits with the task ID in the subject: `feat(core): 1.1 keychain-backed SessionStore`.
- When you are unsure of an SDK or platform API name, open the source in `.build/checkouts/` or the Xcode documentation and confirm it. Never guess a modifier or an endpoint path.
- When a task is underspecified, choose the simplest option that meets the mission and note the choice in the PR. Reversible decisions do not need approval; irreversible ones (data formats on disk, Keychain item layout, bundle ID, entitlements) do.
- Never commit secrets, server URLs, usernames or real media titles from the owner's library. Fixtures use public-domain titles only.
- Do not add "TODO" placeholders for things that are in scope for the current task. Finish the task.
